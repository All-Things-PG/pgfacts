# Glossary

The glossary explains terms and abbreviations used throughout the Phase 2 documentation. It will grow as the project develops.

<table class="topic-table">
  <thead>
    <tr>
      <th scope="col">Our Term</th>
      <th scope="col">Our Meaning</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td><strong>ASP.NET Core</strong></td>
      <td>Microsoft framework used to build web applications. The proof of concept uses ASP.NET Core with Razor Pages.</td>
    </tr>
    <tr>
      <td><strong>Azure</strong></td>
      <td>Microsoft cloud platform for hosting applications, databases, files, and related services.</td>
    </tr>
    <tr>
      <td><strong>BlockInfo</strong></td>
      <td>A database field that can hold optional layout or display instructions for a content element.</td>
    </tr>
<tr>
      <td><strong>Content</strong></td>
      <td>Any information that can be added to the Knowledge Base (KB).  In its most basic form, Content is was displays on a page when you click a menu item.  That concept will be expanded over time.  Content is not just article, it can be patient stories, on-going research, clinical-trials, videos etc. </td>
    </tr>
    <tr>
      <td><strong>Content Card</strong></td>
      <td>A reusable display area for one content element, such as a text block or image.</td>
    </tr>
    <tr>
      <td><strong>Content Document</strong></td>
      <td>A database record describing a page or article and connecting it to its content elements.</td>
    </tr>
    <tr>
      <td><strong>Content Element</strong></td>
      <td>An individual piece of a content document, such as text, markup, or a media reference.</td>
    </tr>
    <tr>
      <td><strong>Content Type</strong></td>
      <td>A label that identifies the kind of content document, such as an article or gallery.</td>
    </tr>
<tr>
      <td><strong>Curate</strong></td>
      <td>TCurate is the process of gathering Content.  The concept is to author or discover new content, add it to a staging environment, organize, review, improve, and finally approve.  In some cases after medical review.  Once vetted, then we ccan publish.  Pubished content is moved to the production environment as trusted informationo.</td>
    </tr>
    <tr>
      <td><strong>Database Project</strong></td>
      <td>The source project that defines database tables and other database objects and can build a deployment package.</td>
    </tr>
<tr>
      <td><strong>DCMS</strong></td>
      <td>Dynamic Content and Menuing System is the backbone of the database design.  It allows for data-driven webpages that display content fromothe database, and a customized set of menu items based on the user type. Dynamic menus also allow for different content to be display for the same menu item.  A doctor could receive and in-depth clinical discussion, where a Caregiver would be more user friend. </td>
    </tr>
    <tr>
      <td><strong>Deployment</strong></td>
      <td>The process of placing a built application or website into an environment where people can use it.</td>
    </tr>
<tr>
      <td><strong>Documentation site</strong></td>
      <td>This website, which presents the Phase 2 plans, analyses, designs, technical specifications, and project background for review.</td>
    </tr>
    <tr>
      <td><strong>Email Preference</strong></td>
      <td>A visitor choice to receive a particular category of email, such as a newsletter or research update.</td>
    </tr>
    <tr>
      <td><strong>Environment</strong></td>
      <td>A separate setup used to build, review, or run software, such as development, staging, or production.</td>
    </tr>
    <tr>
      <td><strong>Foreign Key</strong></td>
      <td>A database field that refers to a record in another table, helping preserve the relationship between the records.</td>
    </tr>
    <tr>
      <td><strong>Full-Text Indexing</strong></td>
      <td>A database search feature that indexes words in text so searches can find relevant content efficiently.</td>
    </tr>
    <tr>
      <td><strong>GitHub Pages</strong></td>
      <td>A GitHub service that publishes a website generated from files stored in a repository.</td>
    </tr>
    <tr>
      <td><strong>IIS</strong></td>
      <td>Microsoft web server software that can host web applications.</td>
    </tr>
<tr>
      <td><strong>Knowledge Base (KB)</strong></td>
      <td>A searchable, organized collection of reviewed information about PG and related topics for different types of visitors.</td>
    </tr>
    <tr>
      <td><strong>Lookup Table</strong></td>
      <td>A database table that holds an approved list of values used by other records, such as visitor or route types.</td>
    </tr>
    <tr>
      <td><strong>Menu Item</strong></td>
      <td>A database record for a navigation choice, including its label, position, audience visibility, and destination.</td>
    </tr>
    <tr>
      <td><strong>Metadata</strong></td>
      <td>Information that describes another record or file, such as its title, type, status, or dates.</td>
    </tr>
    <tr>
      <td><strong>Migration</strong></td>
      <td>The planned transfer of existing website content or data into a new system while preserving its meaning and relationships.</td>
    </tr>
    <tr>
      <td><strong>MIME Type</strong></td>
      <td>A label that identifies the kind of file or content being handled, such as an image or HTML document.</td>
    </tr>
    <tr>
      <td><strong>Persona</strong></td>
      <td>A description of a visitor group, used to shape the information and experience presented to that audience.</td>
    </tr>
<tr>
      <td><strong>Phase 1</strong></td>
      <td>The existing All Things PG website and its initial content and capabilities.</td>
    </tr>
<tr>
      <td><strong>Phase 2</strong></td>
      <td>The proposed next stage of development, adding a database, searchable content, dynamic menus, and enhanced visitor experiences.</td>
    </tr>
    <tr>
      <td><strong>Pipeline</strong></td>
      <td>An automated sequence of steps for building, checking, and possibly deploying software.</td>
    </tr>
<tr>
      <td><strong>Portal</strong></td>
      <td>A customized view of the website making in more attractive and more appropriate to the type of user. The pages delived are tailored to the needs and interests of a particular audience. There are no functional difference between Portals, is just how you and feel within the website that it belongs to you.</td>
    </tr>
    <tr>
      <td><strong>Primary Key</strong></td>
      <td>A field, or group of fields, that uniquely identifies each record in a database table.</td>
    </tr>
    <tr>
      <td><strong>Production</strong></td>
      <td>The live environment used by the website audience.</td>
    </tr>
<tr>
      <td><strong>Proof of Concept (POC)</strong></td>
      <td>A limited working prootype used for demonstration, and to prove key element (likd DCNS) are possible.</td>
    </tr>
    <tr>
      <td><strong>Razor Pages</strong></td>
      <td>An ASP.NET Core approach for building web pages with server-side processing.</td>
    </tr>
    <tr>
      <td><strong>Registration</strong></td>
      <td>A record created when a visitor provides basic details, such as an email address and visitor type. Registration does not necessarily mean creating a login.</td>
    </tr>
    <tr>
      <td><strong>Relational Database</strong></td>
      <td>A database that stores information in tables and connects related records using keys.</td>
    </tr>
    <tr>
      <td><strong>Route Target</strong></td>
      <td>The value on a menu item that identifies the page, content, visitor experience, or destination to open.</td>
    </tr>
    <tr>
      <td><strong>Route Type</strong></td>
      <td>The category of a menu destination: Visitor, Content, Page, or Redirect.</td>
    </tr>
    <tr>
      <td><strong>Schema</strong></td>
      <td>The defined structure of a database, including its tables, fields, data types, keys, constraints, and relationships.</td>
    </tr>
    <tr>
      <td><strong>SQL Server</strong></td>
      <td>Microsoft relational database system used by the AllThingsPG database project.</td>
    </tr>
    <tr>
      <td><strong>SQL Server Management Studio (SSMS)</strong></td>
      <td>Microsoft desktop application for connecting to and managing SQL Server databases.</td>
    </tr>
    <tr>
      <td><strong>Staging</strong></td>
      <td>An environment where content or software can be prepared and reviewed before it reaches the live site.</td>
    </tr>
<tr>
      <td><strong>Stakeholder</strong></td>
      <td>A person or group involved in the project and who have a direct influence over the features to be included in Phase 2.  They have more authority over the projects for approvals, budgets and timelines.</td>
    </tr>
    <tr>
      <td><strong>Static Website</strong></td>
      <td>A website served from pre-generated files, rather than assembling each page from database content when requested.</td>
    </tr>
    <tr>
      <td><strong>Stored Procedure</strong></td>
      <td>A named set of SQL instructions saved in the database and run to perform a task.</td>
    </tr>
<tr>
      <td><strong>Tenant</strong></td>
      <td>On approval of the nonprofit grant for MS 365 Business Basic licenses, Microsoft provided us with a tenant, which is a workspace or environment to exists as our own organization, with our own custom domain (allthingpg.org).  It essentially creates sus a Technology Plaform from which to a nonprofit organization now and into the future with unlimited growth.</td>
    </tr>
<tr>
      <td><strong>Tiles</strong></td>
      <td>A Tile Panel will display at the top of each page, each with 3 tiles. Each tile will have a header and a description.  These are essentially menu items with links to another page.  The purpose of the tiles is to give a more guided experience, showing the user what might be interesting to review next.  The set of tilesis  customized for that page, and links to the otehr page of interest.</td>
    </tr>
    <tr>
      <td><strong>UML</strong></td>
      <td>Unified Modeling Language, a set of diagram conventions used to describe software systems and their structure.</td>
    </tr>
    <tr>
      <td><strong>Visitor Experience</strong></td>
      <td>The way information and navigation are tailored to the needs of a visitor or selected visitor type.</td>
    </tr>
    <tr>
      <td><strong>Visitor Mask</strong></td>
      <td>A menu setting that controls which visitor types see an item; it controls visibility, not permission to access data.</td>
    </tr>
<tr>
      <td><strong>Visitor Type</strong></td>
      <td>In Phase 2, each user will have a Visitor Type, which is either Patient, Caregiver, Provider, Pharmaceutical, or Guest by default. The Visitor Type sets the menu and the portal for an enhanced user  experience.</td>
    </tr>
    <tr>
      <td><strong>Workflow Status</strong></td>
      <td>A label showing where content is in its review and publication process, such as draft or approved.</td>
    </tr>
    <tr>
      <td><strong>WYSIWYG</strong></td>
      <td>What You See Is What You Get: an editor that shows content in a form close to how it will appear when published.</td>
    </tr>
  </tbody>
</table>
